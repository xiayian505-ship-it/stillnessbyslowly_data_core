Reward Claim Flow｜獎勵逐項領取

接收宿主已產生的獎勵，逐項等待決策；提交後須由宿主 commit 才推進，支援 snapshot 與 pending 中斷恢復。

一、載入方式

本地開發測試：

<script src="./reward_claim_flow.js"></script>

正式部署在你的軍火庫後，其他宿主可以採絕對網址：

https://lib.stillnessbyslowly.com/state/reward_claim_flow.js

注意：本 ZIP 尚未部署，上列 HTTPS 網址為預計發布路徑，不代表目前已上線。

二、公開 API

全域物件：SlowlyRewardClaimFlow；版本 1.0.0。錯誤輸入通常丟出 TypeError／RangeError／Error，應由宿主捕捉。

函式用途與輸入輸出
create() / start(items, {flowId?})建立新流程；items 各需唯一字串 id；建議宿主傳穩定 flowId
current()目前待處理獎勵，若無則 null
accept(details?) / reject(reason?)回傳待提交的決定，不直接領取或推進
replace(targetId)提出替換決定，targetId 必填
commit(decisionId)宿主確實成功處理後提交，回傳 committed / completed
cancel(decisionId)宿主失敗時撤銷待提交決定，游標保持原位
snapshot() / restore(data)保存、還原待提交與已確認決定
isComplete()查詢整批是否完成

三、最小使用範例

const flow = SlowlyRewardClaimFlow.create();
flow.start([{ id: "reward_a", name: "獎勵 A" }], { flowId: "battle_202" });
const decision = flow.accept();
// 宿主先依 decision.decisionId 做可重試去重的永久收藏更新。
const hostSucceeded = true;
if (hostSucceeded) flow.commit(decision.decisionId);
else flow.cancel(decision.decisionId);

四、相依及宿主責任

核心獨立運作，沒有強制依賴任何其他軍火庫零件。這不代表要重做既有能力：宿主仍應使用適當的軍火庫零件處理逐字效果、導航、牌組合法性、卡牌升級與儲存等工作。

本核心無跨存檔交易保證。宿主若在「資產已更新、commit 前」當機，恢復後必須用 decisionId 於自己的存檔去重，才能避免重複領取。領獎方案、升級、收藏上限皆屬宿主。
