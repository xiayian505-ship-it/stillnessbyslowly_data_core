Slowly Card Strategy Component v1.0.0

通用策略卡牌「完成品」，不是只有引擎。內建收藏、升級、組牌與策略對戰的可操作畫面，並有 20 張示範牌及可用的基本規則。外觀只有必要 CSS，所有素材與遊戲世界觀由宿主提供。

3. 零設定就能用

<div id="strategy-game"></div>
<script>
  const game = SlowlyCardStrategy.mount("#strategy-game");
</script>

掛載後先顯示收藏：可以點上方頁籤進行升級、組牌，再按開始戰鬥。也可設定 autoStart: true 直接進入戰鬥。預設玩法：20 張牌、30 HP、行動點 3／魔法點 3、回合補手牌至 5、一次免費換牌、Lv.5 上限、玩家與簡單電腦輪流行動。

若已載入設定檔：SlowlyCardStrategy.mount("#strategy-game", SlowlyCardStrategyConfig)。

4. 宿主設定入口

options用途
participants參與者資料陣列，每位需要唯一 id、name、maxHP、hp、shield、ai；預設為 player 與 opponent。
controlledParticipant目前 UI 控制者 ID，預設 player；非控制者可交給 aiTurn 處理。
cards示範卡種清單。每種含 cardId、name、copies、cost（多資源物件）、target、effects 陣列；用來建立預設收藏。
collection宿主提供的實體卡陣列，每張必須有唯一 id 及 cardId；為 null 時使用 cards 建立。
loadoutIds已選入出戰牌組的實體 ID 陣列；為 null 時自動預選前 deckSize 張。
opponentCards非 UI 控制者的示範牌來源；預設 cards。
upgradeTokens初始升級點數，預設 5。
resources各資源的基本值，例如 {action: 3, mana: 3}。
rules牌組容量、手牌數、升級上限、回合行為及可覆蓋判定函式。
effects以 effect.type 為 key 的 CardEffectRegistry 執行函式或 {canRun, execute}；同名替換預設、設 false/null 停用。
actions.aiTurn宿主替換整個電腦回合行為。
rendererscollectionCard、combatant、handCard，可替換卡牌／角色呈現內容。
formatters.number決定顯示數字格式。
layout{layouts, fan}：分別傳給 SlotStageLayout 和 HandFanLayout 的原生設定。
feedbackanimation、sound、vibration 開關；slash（ImpactSlash 原生 options）、vibrationPattern、flightDuration。
callbacksonStart、onTurnStart、onCardPlay、onUpgrade、onFinish、onStateChange、onError。

5. 預設卡牌效果與目標

effect.type實際使用的軍火庫核心目標
attack / guard / healCombatStats：傷害、護盾、治療opponent / self
drawDeck.draw()none
resourceCardResourcePoolnone
discardCardTargetSelection → CardZoneTransfer.moveCard()opponent-hand
redrawCardTargetSelection → CardZoneTransfer.moveCard() → Deck.draw()self-hand（另一張手牌）
exchangeCardTargetSelection → CardZoneTransfer.swapCards()opponent-hand

角色目標（participantId）與手牌目標（owner、zone、cardId）不同。CardTargetSelection 的候選只適用於卡牌區；不要假定它會處理角色血量。預設卡牌效果可用 effects 真正替換，而不是在預設效果後面再追加一次。

6. 規則完整覆蓋

宿主明確提供的函式優先於預設行為。核心預設僅為能遊玩而存在。以下函式均為同步呼叫；自訂操作不得直接破壞 Deck 的 snapshot 結構。

rules 屬性作用與覆蓋範圍
deckSize / minimumDeckSize / handSize / maximumLevel出戰容量、最低張數、手牌目標與升級上限。
freeSwapsPerTurn / aiCardsPerTurn / refillEachTurn免費換牌次數、電腦出牌量與是否回滿資源。
isLoadoutEligible(card, context)單張卡是否允許編組。
validateLoadout({cards,ids,game})完整牌組額外驗證；傳回 false 或 {valid:false,reason} 即拒絕開始戰鬥。
upgradeCost(card,context)單張卡升級費用（非負數字）。
canUpgrade(card,context)可否升級；回傳 false 拒絕。
effectAmount({game,card,effect,level})覆蓋預設 amount + (Lv-1) 公式。
getCost({game,card,actorId,battle})完整替換出牌費用（例如 {action:1,mana:2}）。
canPlay({game,card,actorId,target})整體出牌合法性；false 拒絕。
getTargetType({game,card,actorId})修改內建目標類型。
getTargets(context)取代候選目標產生流程；回傳 undefined 使用內建。
isEligibleTarget({game,card,actorId,candidate})篩選手牌類目標。
resolveTarget({game,card,actorId,requestedTarget})完整覆蓋目標解決；回傳 {type,target,candidate}、{needsSelection:true,candidates} 或 {invalid:true}。
onTurnStart({game,participantId,pool,deck,battle})完全取代預設每回合補資源及補牌。
onTurnEnd({game,participantId,pool,deck,battle})完全取代預設回合末棄光手牌。
advanceTurn({game,battle,turnOrder})取代預設 turnOrder.advanceTurn()；宿主須自行正確推進以免卡住。
checkVictory({game,battle,participants})完全取代預設 HP 歸零判定。回傳 null/false 代表未結束、字串代表 winner ID 或 "draw"。
const game = SlowlyCardStrategy.mount("#strategy-game", {
  rules: {
    checkVictory({ participants }) {
      // 這裡完整取代內建 HP 歸零判定：宿主決定何時有人勝出。
      return null;
    },
    upgradeCost(card) {
      return card.level * 2;
    }
  },
  effects: {
    attack(context) {
      // 宿主替換攻擊效果；預設攻擊函式不會再執行。
      return CombatStats.damage(context.target, 9);
    }
  },
  callbacks: {
    onFinish({ winner }) { console.log("winner:", winner); }
  }
});

如需完全自訂任意形狀的特殊目標 UI，宿主應搭配 getTargets/resolveTarget、Renderer 和公開的 chooseTarget()，將選擇結果回傳。預設 HTML 只提供角色與手牌的標準目標按鈕。角色操作界面預設只直接控制一位 controlledParticipant；額外人類玩家介面由宿主整合。

7. 公開實例 API

API用途
start(), restart()使用目前牌組開始／重開一場戰鬥，回傳 {started,...}。
setScreen("collection" | "upgrade" | "loadout" | "battle")切換內建操作頁。
upgradeCard(instanceId)對收藏實體卡升級，回傳 {ok,...}。
addToLoadout(id), removeFromLoadout(id), moveLoadoutCard(id, -1 | 1)編輯出戰牌組。
getLoadoutValidation()取得 CardLoadoutValidation 結果及最少張數檢查。
playCard(index, target?, actorId?)出牌；對需要選目標的牌可先不傳 target，再呼叫 chooseTarget。
chooseTarget(target), cancelTarget()確認／取消操作；角色目標為 {participantId}，手牌目標為 {owner,zone:"hand",cardId}。
mulligan(index), endTurn()免費換掉指定手牌、結束回合並推進 AI。
setFeedbackEnabled("animation" | "sound" | "vibration", enabled)切換特效／音效／震動；影響外觀回饋，不改遊戲結果。
setLayouts(layouts)傳入 SlotStageLayout 原生布局陣列，直接替換插槽排列。
getState(), snapshot(), restore(snapshot), destroy()完整狀態與生命週期。renderers 與 callbacks 不會進入 JSON。

8. Snapshot / restore 與失敗復原

快照包括收藏、牌組 ID、升級點數、所有對戰者、雙方 Deck 三區與 sourceItems、多資源數值、回合順序與戰鬥紀錄。目標選擇中的短暫 UI 對話不保存；還原後需重新選取。永久儲存（FictionStorage、後端或使用者自備的其他資料庫）由宿主負責。

出牌在驗證合法目標及費用後才執行；執行中發生例外時，完成品用 snapshot/restore 回復所有戰鬥數值與牌區，不回滾宿主自行進行的外部 I/O、音效、資料庫或 DOM 副作用。預設的 CardEffectRegistry 沒有自動交易功能，因此回滾協調位於完成品。

9. UI 與可替換的 CSS

戰鬥舞台具五個插槽：enemy、center、hand、player、controls，由 SlotStageLayout 負責 Grid 模板；扇形交給 HandFanLayout。兩者皆按容器寬度調整布局。

完成品 CSS 不提供霧林專屬配色。可覆寫 --scs-gap、--scs-border、--scs-surface、--scs-text、--scs-card-width、--scs-card-height、--scs-meter-fill 等變數。宿主可以更換任意卡面美術和視覺 Renderer。

10. 已知邊界與測試

預設勝負依 CombatStats 判定；預設簡易 AI 最多每回合使用 aiCardsPerTurn 張可出牌卡，並非強大 AI。角色目標與卡牌目標分開處理。預設音效需要在使用者互動後播放，且受瀏覽器自動播放政策限制。手機震動也受裝置／瀏覽器支援限制。
