Rejected Asset Routing｜放棄資產歸屬分配

產生保留、放棄、替換的歸屬計畫；不執行資產資料修改，不預設接收方是敵人。

一、載入方式

本地開發測試：

<script src="./rejected_asset_routing.js"></script>

正式部署在你的軍火庫後，其他宿主可以採絕對網址：

https://lib.stillnessbyslowly.com/state/rejected_asset_routing.js

注意：本 ZIP 尚未部署，上列 HTTPS 網址為預計發布路徑，不代表目前已上線。

二、公開 API

全域物件：RejectedAssetRouting；版本 1.0.0。錯誤輸入通常丟出 TypeError／RangeError／Error，應由宿主捕捉。

函式用途與輸入輸出
splitBySelection(items, selectedIds, options?)options.destination 放棄時必填；依實體 ID 分成 kept／transferred
planRejection(item, destination, options?)新獎勵遭放棄的待轉移計畫（不假設先歸玩家所有）
planReplacement(newItem, oldItemId, destination, {ownedItems})驗證指定舊物品確實持有後，產生替換計畫
validatePlan(plan, context?)檢查唯一性、目的地、removedIds 來源存在；回傳 isValid / errors

三、最小使用範例

const pool = [{ id: "one", cardId: "attack" }, { id: "two", cardId: "attack" }];
const result = RejectedAssetRouting.splitBySelection(pool, ["one"], {
  destination: "other_owner"
});
const checked = RejectedAssetRouting.validatePlan(result, {
  availableIds: pool.map(card => card.id)
});
// 檢查成功後，宿主自行原子化套用 result；核心不改 pool。

四、相依及宿主責任

核心獨立運作，沒有強制依賴任何其他軍火庫零件。這不代表要重做既有能力：宿主仍應使用適當的軍火庫零件處理逐字效果、導航、牌組合法性、卡牌升級與儲存等工作。

僅提出分配計畫，不做交易或跨儲存回滾；資料 ID 需唯一，宿主應檢查擁有者資料並以原子性更新。planRejection 對新獎勵不會虛構玩家移出紀錄。
