Auth_permission_ui.js v1.0.0

共用的前端登入／登出／身份／權限 UI 狀態模組。它不綁 Supabase、Firebase 或 PHP，也不負責真正的安全驗證。

1. 它負責什麼

登入表單送出、登入中狀態、錯誤訊息、登入後隱藏登入表單、顯示登出與已登入區塊，以及依 role / permissions 控制前端元素顯示。

2. 它不負責什麼

不驗證帳密、不保存 session/token、不直接連資料庫、不判斷真正資料權限，也沒有註冊、忘記密碼、重設密碼、Email 驗證與帳號申請。

3. 最小 HTML 標記

<section id="authRoot">
  <div data-auth-status></div>
  <div data-permission-status></div>
  <form data-auth-form>
    <input data-auth-account>
    <input data-auth-password type="password">
    <button data-auth-submit>登入</button>
    <div data-auth-message></div>
  </form>
  <button data-auth-logout hidden>登出</button>
</section>

4. JS 接口

const ui = AuthPermissionUI.create({
  root: "#authRoot",
  async onLogin({ account, password }, ui) {
    // 1. 把帳密送到真正 Auth API
    // 2. 從後端取得可信任的身份 / role / permissions
    // 3. 再把結果交給 UI
    ui.setState({
      role: "editor",
      permissions: ["read", "edit"],
      statusText: "已登入｜小明",
      permissionText: "編輯權限"
    });
  },
  async onLogout(ui) {
    // 先讓真正後端/session/token 登出或失效
    ui.setState({ role:"guest", permissions:[] });
  }
});
接口用途
onLogin(data, ui)宿主接真正登入 API 的位置。data 只有 account/password。
onLogout(ui)宿主接真正登出 / session 失效的位置。
ui.setState(state)把後端已確認的 role / permissions / 顯示文字交給 UI。
ui.getState()讀取目前前端 UI state；不能拿它當後端授權證明。
ui.setMessage()設定登入訊息。
ui.clearPassword()清除密碼欄。
ui.clearCredentials()清除帳號與密碼欄。

5. 權限顯示

<div data-auth-visible="guest">只有未登入看得到</div>
<div data-auth-visible="authenticated" hidden>登入後看得到</div>
<button data-permission="edit" hidden>編輯</button>
<button data-permission="read edit" data-permission-mode="all" hidden>需要 read + edit</button>

data-permission 預設 any；加 data-permission-mode="all" 才要求全部符合。role 本身也會加入比對，因此 data-permission="admin" 可對 role=admin 顯示。

6. 安全界線：資料庫／後端要負責

前端隱藏按鈕不是權限。 使用者可以自己修改 DOM 和 JS。

後端／資料庫必須真正驗證：登入憑證、session/token、user id、role/permissions、每筆資料的讀取權、建立權、修改權、刪除權、資源歸屬，以及管理者操作。Supabase 專案應以 RLS/policy 落實；其他後端則由 Security Rules、API middleware 或 server-side authorization 落實。

7. CSS

Auth_permission_ui.css 只提供 grid、欄位寬度、responsive 與 hidden 必要規則，不設定主題色、圓角、陰影等視覺風格，外觀由宿主網站 CSS 負責。

8. 建議接法

頁面載入 → 宿主先向後端確認目前 session → 得到可信任身份後呼叫 ui.setState()。登入時由 onLogin 呼叫 Auth API；登出時由 onLogout 呼叫真正登出接口。所有資料 CRUD 仍直接走有後端權限驗證的資料接口，不經由本模組授權。
