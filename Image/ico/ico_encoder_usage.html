ICO Encoder v1.0.0｜使用說明

ICO Encoder 將一張或多張已經編碼完成的正方形 PNG 位元組封裝成 ICO Blob。 它不是 PNG 副檔名修改器、ICO 解碼器，也不負責繪製圖示。

新零件部署後的正式絕對路徑：

公開 API

全域物件：window.SlowlyICOEncoder，API 以 Object.freeze 凍結。

SlowlyICOEncoder.version                  // "1.0.0"
SlowlyICOEncoder.encode(pngEntries)       // 同步回傳 ICO Blob

pngEntries 必須是非空陣列，元素形如 { size: 16, data: pngBytes }。 size 必須是 1～256 的整數，代表正方形 PNG 的寬和高； data 必須是完整的 PNG Uint8Array， 不能傳入 Canvas、Blob、Data URL、Base64 字串或未壓縮的 RGBA 像素。 同一個 ICO 不允許重複尺寸，輸出順序與輸入順序相同。 

const iconBlob = SlowlyICOEncoder.encode([
  { size: 16, data: png16Bytes },
  { size: 32, data: png32Bytes },
  { size: 256, data: png256Bytes }
]);

console.log(iconBlob.type); // "image/x-icon"

宿主整合範例

宿主負責取得圖片及繪製不同尺寸的 Canvas。 SlowlyCanvasPNG.toBlob(canvas) 是既有軍火庫的非同步方法； 用 blob.arrayBuffer() 和 Uint8Array 轉成 ICO 核心需要的位元組。 以下假設宿主已建立尺寸正確的兩張 Canvas。 

async function createIcoFromCanvases(canvas16, canvas256) {
  const inputCanvases = [
    { size: 16, canvas: canvas16 },
    { size: 256, canvas: canvas256 }
  ];

  const pngEntries = [];

  for (const input of inputCanvases) {
    // 共用軍火庫核心負責 Canvas → PNG，不要在宿主複製該核心。
    const pngBlob = await SlowlyCanvasPNG.toBlob(input.canvas);

    if (pngBlob.type !== "image/png") {
      throw new TypeError("Canvas 沒有產生 PNG Blob。");
    }

    const pngBytes = new Uint8Array(await pngBlob.arrayBuffer());
    pngEntries.push({ size: input.size, data: pngBytes });
  }

  return SlowlyICOEncoder.encode(pngEntries);
}

下載與 URL 回收

ICO Encoder 不負責下載。既有 SlowlyPNGDownload 只支援 PNG，不能拿它替代 ICO 下載。 使用 Blob URL Scope 管理 Object URL，並由宿主建立下載連結。 

const iconBlob = await createIcoFromCanvases(canvas16, canvas256);
const scope = BlobUrlScope.create();
const iconUrl = scope.create(iconBlob);

const downloadLink = document.createElement("a");
downloadLink.href = iconUrl;
downloadLink.download = "favicon.ico";
downloadLink.textContent = "下載 ICO";
document.body.appendChild(downloadLink);

// 下載連結仍要提供使用時，不要提前 revoke。
// 宿主不再需要此下載連結時，才回收 URL：
function removeDownloadLink() {
  downloadLink.remove();
  scope.revoke(iconUrl);
  scope.destroy();
}

ICO 封裝規則

ICO 開頭是 6 bytes 的 ICONDIR，接著每張圖有 16 bytes 的 ICONDIRENTRY， 最後依序放置各張 PNG 的完整位元組。多位元組數值使用 little-endian。 寬高欄位寫入 1～255，256 px 則寫入 0（ICO 格式慣例）。 Color planes 為 1，bit count 欄位為 32，沿用原作的封裝設定。 這是 PNG-in-ICO，不會生成舊式 BMP／AND-mask 圖示。

圖片縮放及原始格式

contain（完整置入）、cover（裁切填滿）、 stretch（拉伸）及背景色／透明度，全部由宿主的 Canvas 繪製邏輯負責，不屬於 ICO Encoder。 既有 ImageResize.resize() 也不能直接替代這三種模式。

本次 Demo 比照原始 ico.html 接受 PNG、JPG（JPEG）、GIF、SVG、 WebP、BMP，及其他瀏覽器標示為 image/* 且可解碼的圖片格式。 即使原始 SVG 缺少 MIME，Demo 也會在建立圖片 Object URL 前補上 image/svg+xml；部分 SVG 沒有內建尺寸時，Canvas 繪製沿用原作的 256 px 備用尺寸。是否真的能解碼仍取決於瀏覽器與檔案內容。 ICO 核心本身始終只接受已編碼完成的 PNG 位元組。 使用一般 <img>／Canvas 讀取 GIF 並不能保證抽取動畫第一格， 不應宣稱具備專門的首格抽取能力。

參數錯誤與限制

  • 型別錯誤（例如空陣列、非 Uint8Array、PNG 結構損壞）：拋出 TypeError。
  • 範圍或容量錯誤（例如尺寸超出 1～256、重複尺寸、PNG 實際尺寸不符）：拋出 RangeError。
  • 會檢查 PNG 簽章、第一個 IHDR、IHDR 尺寸、chunk 邊界、至少一個 IDAT 與完整 IEND。
  • 不校驗 CRC、不解壓 IDAT，也不是 PNG 解碼器、消毒工具或惡意內容掃描器。
  • v1 明確限制整個 ICO 最多 134217728 bytes（128 MiB）；超過時在配置 ICO ArrayBuffer 前拒絕。
  • 同時檢查 ICO uint32 長度／位移、uint16 圖片數量以及 JavaScript 安全整數界線。
  • 編碼過程不更改呼叫者的陣列或位元組；回傳 Blob 不受來源 Uint8Array 後續修改影響。

未經信任的 SVG 或跨來源遠端圖片可能帶來安全風險； 遠端圖片還可能使 Canvas 受到跨來源限制（tainted canvas），導致 PNG 輸出失敗。 建議宿主自行限制檔案來源、大小及可接受類型，必要時透過瀏覽器實際解碼驗證。 部分舊系統／ICO 讀取器不支援所有 PNG-in-ICO 組合， 不可在未實測的情況下宣稱全面相容。
