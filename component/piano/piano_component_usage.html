Slowly Piano v1.2.0

手機／觸控友善的鋼琴完成品。 宿主可以決定音域、排版、 捲動方向、可視範圍與外觀。

piano_config.js 是可選純資料設定。 不載入時， Component 仍會使用內建預設。

為什麼 A0 附近像沒聲音？

A0 只有 27.5 Hz。 Web Audio 確實有產生正確基頻， 但手機與小型喇叭通常很難有效重播 這類極低頻。

v1.2.0 預設開啟低頻輔助： 基頻仍然保留， 只是另外加較小聲的 2 倍與 3 倍泛音， 讓手機比較能聽見低音。 

lowFrequencyAssist: {
  enabled: true,
  belowHz: 130,
  sineOnly: true,

  harmonics: [
    {
      multiple: 2,
      gainRatio: 0.30
    },
    {
      multiple: 3,
      gainRatio: 0.18
    }
  ]
}

若要完全純粹的單一 Oscillator： 

lowFrequencyAssist: {
  enabled: false
}

音域 

range: {
  from: "A0",
  to: "C8"
}

A0～C8 是標準 88 鍵音域。 也可以任意裁成例如 C3～B5。

垂直捲動 

layout: {
  scrollDirection: "vertical",

  whiteKeysPerRow: 7,

  visibleRows: 3,

  visibleWhiteKeys: 7
}

whiteKeysPerRow 是每排幾個白鍵。 黑鍵是覆蓋在白鍵之間， 不拿來當等寬欄位計算。

visibleRows: 3 代表畫面同時顯示三排， 其他排往下捲。

水平捲動 

layout: {
  scrollDirection: "horizontal",

  visibleWhiteKeys: 8,

  whiteKeysPerRow: 7,
  visibleRows: 1
}

水平模式會把整個音域排成 一條連續鋼琴並左右捲動。

visibleWhiteKeys 控制 viewport 大約顯示幾個白鍵寬。 水平模式只有一條琴鍵， 所以 whiteKeysPerRow 與 visibleRows 不參與分排。

為什麼設定的是白鍵數？

因為鋼琴黑鍵是覆蓋在兩個白鍵之間， 不是真正獨立的一個等寬欄位。 如果直接「每 12 個實體鍵硬切一排」， 很容易剛好切在黑鍵中間， 造成下一排的琴鍵幾何不自然。

設計邊界

Slowly Piano 負責琴鍵排列、 發聲、多指操作與 layout。 音準仍交給 SlowlyAudioNoteFrequency。 宿主決定音域、捲動方向、 每排白鍵數、可見排數與皮膚。
