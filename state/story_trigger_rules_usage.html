Story Trigger Rules｜劇情觸發規則

對宿主提供的 context 執行 callback 條件，分別判斷章節解鎖與事件觸發，穩定排序所有符合的候選。

一、載入方式

本地開發測試：

<script src="./story_trigger_rules.js"></script>

正式部署在你的軍火庫後，其他宿主可以採絕對網址：

https://lib.stillnessbyslowly.com/state/story_trigger_rules.js

注意：本 ZIP 尚未部署，上列 HTTPS 網址為預計發布路徑，不代表目前已上線。

二、公開 API

全域物件：SlowlyStoryTriggerRules；版本 1.0.0。錯誤輸入通常丟出 TypeError／RangeError／Error，應由宿主捕捉。

函式用途與輸入輸出
create(rules)rules 是陣列，各項 id、targetId 必填
isUnlocked(targetId, context)存在符合的解鎖規則則為 true
evaluate(eventName, context)依 priority 降冪、同值依登記順序，回傳所有符合規則
shouldTrigger(eventName, context)有至少一個符合候選時回傳 true
getRules()只讀的規則摘要，不含 callback 函式

三、最小使用範例

const triggers = SlowlyStoryTriggerRules.create([{ 
  id: "after_level_2", targetId: "chapter_02", event: "battleWon",
  unlockWhen: context => context.completed >= 2,
  triggerWhen: context => context.auto === true && !context.seen.includes("chapter_02"),
  priority: 10
}]);
const targets = triggers.evaluate("battleWon", {
  completed: 2, auto: true, seen: []
});
// 由宿主決定是否播放 targets[0].targetId。

四、相依及宿主責任

核心獨立運作，沒有強制依賴任何其他軍火庫零件。這不代表要重做既有能力：宿主仍應使用適當的軍火庫零件處理逐字效果、導航、牌組合法性、卡牌升級與儲存等工作。

選擇 callback 而非 JSON 條件語法；規則本身不能直接 JSON 序列化。若缺少必要進度資料，條件應明確回傳 false（只有 ===true 才算命中）；核心不改進度、不跳轉。
