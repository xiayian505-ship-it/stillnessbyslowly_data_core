Replay Player｜已記錄動作播放器

只管理動作序列的位置、播放狀態、定時與速度；不含視覺皮膚、DOM、遊戲規則、動畫、資料庫、錄影或影片格式。

公開介面

SlowlyReplayPlayer.version 為 1.0.0；使用 SlowlyReplayPlayer.create(options) 建立獨立實例。

方法說明
load(actions)載入 JSON 可序列化的動作陣列，複製內容並重設位置為 0。
play()、pause()、toggle()播放、暫停、切換。播放結尾再按播放會由開頭重新開始。
previous()、next()後退／前進一個動作位置，並暫停播放。
seek(position)定位到 0～動作總數的整數位置，並暫停。位置 0 為原始狀態。
restart()、toEnd()回到開頭／跳到結尾。
setRate(rate)設定正數播放倍率；0.5、1、1.5、2、4 只是宿主可選的介面預設值。
setIntervalMs(ms)設定一般倍率下每一步的時間，預設 800 毫秒。
snapshot()讀取 status、position、total、progress、rate、intervalMs、hasPrevious、hasNext、loaded。
currentAction()、actionAt(index)取得已完成的最後一個動作／指定的 0 起算動作複本。
subscribe(listener)狀態變更時呼叫 listener(state, eventType)，回傳解除訂閱函式。
destroy()停止計時、解除訂閱並釋放動作資料；實例不可再使用。

最小範例

const actions = [
  { from: "A", to: "B" },
  { from: "B", to: "C" }
];
const player = SlowlyReplayPlayer.create({ intervalMs: 800, rate: 1 });

player.subscribe(function (state, eventType) {
  // state.position 是「已完成的動作數」，不是陣列索引。
  // 宿主自行從初始狀態套用 actions.slice(0, state.position)。
  drawStateAt(state.position);
});

player.load(actions);
player.play();
// player.pause(); player.seek(1); player.previous();

狀態和事件

狀態：idle（未載入）、paused、playing、ended、destroyed。播放到最後會通知 complete。其他事件名稱：load、play、pause、tick、seek、rate、interval、destroy。

依賴與宿主責任

  • 獨立瀏覽器 JS，沒有第三方套件或其他軍火庫零件的必要依賴。
  • 動作只是資料；核心不執行移牌、不驗證通關、不新增遊戲步數、不存取 API。
  • 宿主可在收到 tick 時播放動畫；在 seek 時直接重建指定位置的盤面。
  • 回呼是同步通知；若宿主以非同步方式載入或渲染，宿主須自行取消過期渲染，避免快轉時畫面倒退。
  • 播放器的每步計時以瀏覽器定時器為準；背景分頁可能受到節流，並非精確影片影格時鐘。
  • 宿主決定 UI、動畫時長、外觀、進度條、速度選單、儲存方式與播放完成後的返回流程。
  • 參數不合法會拋出 TypeError／RangeError；未載入前操作或 destroy 後操作會拋出 Error。
  • 可選 options.scheduler 注入 setTimeout／clearTimeout，供離線自動測試使用。
