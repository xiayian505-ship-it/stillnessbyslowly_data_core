Blob URL Scope v1.0.0

管理 URL.createObjectURL() 建立的暫時 URL， 讓一批 Object URL 明確隸屬於同一個 scope， 並由 scope 統一回收。

本模組沒有 UI，因此不需要宿主載入 CSS。

引用

<script src="https://lib.stillnessbyslowly.com/data/blob/blob_url_scope.js"></script>

全域名稱：window.BlobUrlScope

基本使用

const scope = BlobUrlScope.create();

const blob = new Blob(["hello"], {
  type: "text/plain"
});

const url = scope.create(blob);

console.log(scope.size);   // 1
console.log(scope.has(url)); // true

scope.revoke(url);

console.log(scope.size);   // 0

整批回收

const scope = BlobUrlScope.create();

const first = scope.create(blobA);
const second = scope.create(blobB);

scope.clear();

console.log(scope.size); // 0
console.log(scope.active); // true

clear() 只會回收目前 scope 內的 URL， scope 本身仍可繼續使用。

Destroy

const scope = BlobUrlScope.create();

const url = scope.create(blob);

scope.destroy();

console.log(scope.active); // false

// destroy 後不可再建立 URL
scope.create(blob); // throws

destroy() 會先回收 scope 內全部 URL， 再把 scope 標記為失效。

非同步 Render 的使用方式

Blob URL Scope 不會自動解決 async race。 它只提供清楚的資源歸屬與 active 狀態。 宿主仍要自行決定哪一輪 render 才是目前有效的一輪。 

let currentScope = BlobUrlScope.create();

async function render(items) {
  currentScope.destroy();

  const scope = BlobUrlScope.create();
  currentScope = scope;

  for (const item of items) {
    const blob = await loadBlob(item.id);

    // 這一輪已經被下一輪淘汰
    if (!scope.active) {
      return;
    }

    const url = scope.create(blob);

    // 宿主自己決定怎麼把 url 放進 DOM
    renderImage(item, url);
  }
}

這種寫法的重點是： 下一輪 render 開始時先 destroy 舊 scope， 舊的非同步流程即使晚回來，也能透過 scope.active 知道自己已失效。

API

API 說明
BlobUrlScope.create(options?) 建立新的 Object URL scope。
scope.create(blob) 建立 Object URL 並登記到目前 scope。只接受 Blob / File。
scope.revoke(url) 回收目前 scope 擁有的指定 URL。成功回傳 true，找不到則 false。
scope.clear() 回收目前 scope 全部 URL，並回傳回收數量。scope 仍可使用。
scope.destroy() 回收全部 URL 並永久停用此 scope。重複 destroy 不會報錯。
scope.has(url) 檢查 URL 是否仍由此 scope 管理。
scope.size 目前 scope 內尚未回收的 URL 數量。
scope.active scope 是否仍可使用。

設計邊界

  • 不處理 IndexedDB。
  • 不處理 Blob 轉 Data URL。
  • 不處理圖片 resize。
  • 不處理 DOM 元素。
  • 不自動取消 fetch / Promise。
  • 不自動判斷哪一輪 render 應該勝出。

它只負責一件事： 誰建立的 Object URL，由誰負責回收。
