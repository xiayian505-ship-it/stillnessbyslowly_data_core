Slowly Card Battle Component

可直接嵌入網站使用的通用卡牌戰鬥完成品。Component 組合 Deck、Combat Stats、Damage Roll、Charge State、Combatant Config 與 Action Pattern，提供預設可玩戰鬥；宿主可只改設定檔，也可進一步擴充卡牌效果、敵人行動、Renderer、Formatter 與 Callback。

1. 檔案

component/game/
├─ card_battle_component.js
├─ card_battle_component.css
├─ card_battle_config.js
├─ card_battle_component_demo.html
└─ card_battle_component_usage.html

card_battle_config.js 是方便宿主直接修改數值與內容的純資料模板，不是必要依賴；Component 本身已有可玩的預設值。

2. 必要依賴與載入順序

六顆 Game 核心為必要依賴。建議先載入核心，再載入設定檔與 Component。

<link rel="stylesheet"
  href="https://lib.stillnessbyslowly.com/component/game/card_battle_component.css">

<script src="https://lib.stillnessbyslowly.com/game/card/deck.js"></script>
<script src="https://lib.stillnessbyslowly.com/game/combat/combat_stats.js"></script>
<script src="https://lib.stillnessbyslowly.com/game/combat/damage_roll.js"></script>
<script src="https://lib.stillnessbyslowly.com/game/combat/charge_state.js"></script>
<script src="https://lib.stillnessbyslowly.com/game/combat/combatant_config.js"></script>
<script src="https://lib.stillnessbyslowly.com/game/ai/action_pattern.js"></script>

<script src="https://lib.stillnessbyslowly.com/component/game/card_battle_config.js"></script>
<script src="https://lib.stillnessbyslowly.com/component/game/card_battle_component.js"></script>

Deck 需使用 1.1.0 或更新版本，因為戰鬥 restore 會使用 Deck.restore()。缺少任何必要核心時，mount 會直接指出缺少哪個 dependency。

3. 最簡單呼叫

完全不提供 options 也能直接開始一場基本戰鬥：

<div id="battle"></div>

<script>
  const battle = SlowlyCardBattle.mount("#battle");
</script>

若有載入附贈設定檔：

const battle = SlowlyCardBattle.mount(
  "#battle",
  SlowlyCardBattleConfig
);

4. 一般宿主：直接改設定檔

如果只是要換數值、角色名稱、Boss 行動或卡牌內容，優先修改 card_battle_config.js，不需要碰 Component。

window.SlowlyCardBattleConfig = {
  player: {
    name: "玩家",
    maxHP: 100,
    energyMax: 5
  },

  enemy: {
    name: "Boss",
    maxHP: 1000000,
    attackMin: 50000,
    attackMax: 300000,
    guardValue: 100000,
    chargeBonus: 200000,
    pattern: ["attack", "guard", "charge", "attack"]
  },

  cards: [/* ... */],

  rules: {
    handSize: 4,
    resetEnergyEachTurn: true
  }
};

Component 不替宿主做數值平衡，也不設定遊戲應該使用多大的 HP 或傷害值。

5. player

欄位用途
name顯示名稱。
maxHP最大 HP。
currentHP初始 HP；省略時由 Combatant Config 使用 maxHP。
shield初始護盾。
energyMax玩家最大能量。
energy初始能量；會限制在 0～energyMax。
meta宿主附加資料，例如 avatar、characterId。Component 不解讀。

6. enemy

欄位用途
name顯示名稱。
maxHP / currentHP / shield戰鬥數值。
attackMin / attackMax敵人 attack 行動的整數擲值範圍。
guardValue敵人 guard 行動增加的護盾。
chargeBonus敵人 charge 每次累積的 bonus；下一次 attack 會全部消耗。
patternAction Pattern 行動循環。內建 action：attack / guard / charge。
meta宿主附加資料，Component 不解讀。

Damage Roll 的 attackMin / attackMax 會依核心規則轉為整數；大型正數可直接使用。

7. cards

每張牌必須有唯一 id。卡牌保持純資料，不在卡牌物件內放 function，方便 snapshot / JSON / Storage。

{
  id: "strike",
  name: "攻擊",
  cost: 1,
  description: "造成 8 點傷害。",
  effects: [
    { type: "attack", amount: 8 }
  ],
  meta: {
    image: "./strike.webp",
    rarity: "SSR"
  }
}

meta 是宿主資料；effects 才是戰鬥機制資料。

8. 複合卡牌效果

effects 是陣列，會依順序執行，因此一張牌可以同時做多件事：

{
  id: "drain",
  name: "吸血斬",
  cost: 2,
  effects: [
    { type: "attack", amount: 8 },
    { type: "heal", amount: 3 }
  ]
}

內建卡牌 effect：

type行為
attack對敵人造成 amount 傷害，使用 Combat Stats 處理護盾與 HP。
guard玩家增加 amount 護盾。
heal玩家恢復 amount HP，不超過 maxHP。
energy玩家恢復 amount 能量，不超過 energyMax。

9. 自訂卡牌效果

特殊遊戲規則放在 mount 的 effects，不要塞進純資料設定檔。

const battle = SlowlyCardBattle.mount("#battle", {
  ...SlowlyCardBattleConfig,

  effects: {
    poison(context, effect) {
      // effect.amount / effect.turns 等欄位由宿主決定。
      // context 提供 player、enemy、deck、charge、pattern、stats 等。
    }
  }
});

對應卡牌仍然只是純資料：

{
  id: "poison-card",
  name: "毒擊",
  cost: 2,
  effects: [
    { type: "poison", amount: 5, turns: 3 }
  ]
}

10. 自訂敵人 action

Action Pattern 只回傳行動名稱；Component 內建 attack / guard / charge。其他名稱由宿主在 actions 實作。

SlowlyCardBattle.mount("#battle", {
  ...SlowlyCardBattleConfig,

  enemy: {
    ...SlowlyCardBattleConfig.enemy,
    pattern: ["attack", "rage", "attack"]
  },

  actions: {
    rage(context) {
      context.setMessage("Boss 進入狂暴狀態。");
      // 宿主自行定義真正效果。
    }
  }
});

11. rules

欄位預設用途
handSize4每個玩家回合以 Deck.drawToHand() 補到的手牌數。
resetEnergyEachTurntrue每個玩家回合開始時是否把 energy 回復到 energyMax。

第一版沒有把所有內部流程都公開成 options，避免設定檔變成難以使用的規則控制台。

12. 實例 API

const battle = SlowlyCardBattle.mount("#battle");

battle.start();
battle.restart();

battle.playCard(0);
battle.endTurn();

const state = battle.getState();
const save = battle.snapshot();
battle.restore(save);

battle.destroy();
API用途
start()以 mount 時設定重新建立戰鬥。
restart()start() 的語意別名。
playCard(index)使用目前手牌 index 的卡牌。
endTurn()結束玩家回合，執行一次敵人行動並進入下一玩家回合。
getState()取得目前完整狀態快照。
snapshot()取得可保存的戰鬥快照。
restore(snapshot)還原戰鬥快照。
destroy()清空 mount 內容並結束實例。

目前沒有 pause()。這個 Component 沒有持續時間軸或自動 ticker；玩家不操作時，本來就不會自行推進。

13. snapshot / restore

snapshot 會保存戰鬥需要恢復的資料：玩家／敵人狀態、能量、回合、Charge、Action Pattern index，以及 Deck 的 drawPile / hand / discardPile / sourceItems / handSize。

const save = battle.snapshot();

// 之後
battle.restore(save);

Renderer、Callback、自訂 effect / action function 不會進入 snapshot。restore 後仍然沿用目前 mount 實例的宿主函式。

14. 可選：Fiction Storage 本機存檔

Card Battle 本身不依賴 localStorage。若宿主要保存戰鬥，可自行把 snapshot 交給 FictionStorage、IndexedDB、Supabase 或其他資料層。

<script src="https://lib.stillnessbyslowly.com/fiction/Fiction_storage.js"></script>
<script>
const store = FictionStorage.create({
  namespace: "my-game"
});

const saves = store.collection("battle-saves");

await saves.upsert({
  id: "current",
  state: battle.snapshot()
});

const save = await saves.get("current");
if (save) battle.restore(save.state);
</script>

FictionChange 不是必要依賴；只有當其他模組也需要訂閱存檔變更時，宿主才需要另外接上。

15. renderers

Component 有最低限度 HTML Renderer；宿主可替換 player、enemy、card 的內容，因此圖片、SVG、Canvas、Three.js、Live2D、video 等都可以由宿主自行掛進容器。

SlowlyCardBattle.mount("#battle", {
  ...SlowlyCardBattleConfig,

  renderers: {
    player(container, context) {
      container.replaceChildren();
      const img = new Image();
      img.src = context.combatant.meta.avatar;
      container.appendChild(img);
    },

    enemy(container, context) {
      // 宿主自己的 Renderer
    },

    card(button, context) {
      button.textContent = context.card.name;
    }
  }
});

Renderer 出錯時 Component 會在 console 明確報錯，並回退到預設顯示，避免單純的視覺 Renderer 讓整場戰鬥失效。

16. formatters

預設數字使用 toLocaleString()。宿主可決定 1000000 要顯示成 1,000,000、100萬、1M 或其他格式。

formatters: {
  number(value) {
    return value >= 1000000
      ? (value / 1000000) + "M"
      : String(value);
  }
}

17. callbacks

callbacks: {
  onStart({ battle, state }) {},
  onTurnStart({ battle, state, turn }) {},
  onCardPlay({ battle, state, card, results }) {},
  onEnemyAction({ battle, state, action, result }) {},
  onStateChange({ battle, state, reason }) {},
  onWin({ battle, state }) {},
  onLose({ battle, state }) {},
  onFinish({ battle, state, result }) {}
}

勝負後 Component 不自行跳頁。若宿主要切換頁面，可在 onWin / onLose / onFinish 中自行接 Navigation 或其他 Router。

18. CSS 與外觀

card_battle_component.css 只保留必要結構、狀態、可操作性與自適應，不提供遊戲專屬皮膚、背景、發光、粒子、稀有度配色或動畫。

宿主可覆寫：

#battle .slowly-card-battle {
  --scb-gap: 0.8rem;
  --scb-border: var(--line);
  --scb-muted: var(--muted);
  --scb-surface: var(--panel);
  --scb-meter-track: var(--surface-soft);
  --scb-hp: var(--danger);
  --scb-shield: var(--accent-secondary);
  --scb-energy: var(--accent);
  --scb-card-bg: var(--card-bg);
  --scb-card-text: var(--ink);
}

元件 CSS 不修改 body 或全站 button；所有規則都限制在 .slowly-card-battle 範圍內。

19. Responsive

Card Battle 自己使用 Container Query，依元件實際獲得的寬度調整版面，而不是依整台裝置 viewport。桌機可並排顯示玩家與 Boss；窄容器會重新排列，手機寬度下手牌改為可水平捲動。

https://lib.stillnessbyslowly.com/ui/responsive.css 可作為宿主網站的共用自適應地基，但不是 Card Battle 的必要依賴。

20. 其他可選整合

Card Battle 保留 callback 與純資料邊界，因此可以由宿主另外整合：

FictionStorage   → 本機戰鬥存檔
FictionChange    → 多模組資料變更通知
Preference       → 音效 / 動畫等玩家偏好
Navigation       → 勝負後頁面跳轉
Audio / Tone     → 出牌、受傷、勝負音效

以上都不是第一版硬依賴。

21. 設計邊界

Component 負責戰鬥流程；宿主負責世界規則與視覺。卡牌資料不帶 function，遊戲數值不由 Component 平衡，永久儲存位置不由 Component 決定，勝負後導航也不由 Component 決定。
